# 공동편집 4단계: 사용자별 되돌리기 (안전한 되돌리기)

3단계(`docs/collab-stage3.md`)까지로 공동편집은 끝까지 돈다. 지금은 공동편집 중 studio 되돌리기가 꺼져 있다
(0002 패치의 `suspendHistory`). 이 단계는 그것을 **내 편집만, 안전할 때만** 되돌리도록 켠다.

## 1. 사용자 결정 (2026-11-27)

- 내 편집만 되돌린다. 다른 사람의 편집은 건드리지 않는다.
- 내 편집 뒤에 다른 사람이 **같은 자리**를 고쳤으면 그 단계는 되돌리지 않는다. "다른 사람이 이후에 고친
  부분이라 되돌릴 수 없습니다" 를 알리고 그 단계는 버린다.
- 겹치지 않으면 혼자 편집할 때처럼 되돌아간다.
- 배경: 겹친 자리를 무조건 되돌리면 의도와 다른 결과가 나온다(Google Docs 식 "항상 되돌림"은 택하지 않음).

## 2. 출발점: studio 의 되돌리기를 그대로 쓴다

- studio 는 명령 37종(`rhwp-studio/src/engine/command.ts`)이 각자 `undo()` 를 갖고, `engine/history.ts` 가
  undo/redo 스택을 관리한다. 입력 묶기(연속 타이핑 = 한 단계)도 studio 규칙을 쓴다.
- 명령의 `undo()` 는 WASM export 를 부른다(`deleteText`·`insertText`·`mergeParagraph`·`setCharShapeRuns`·
  `restoreDeleteFragment`·`restoreSnapshot` 등). 2단계의 export 경계 기록이 이 호출을 그대로 op/state 로 보낸다.
  **되돌리기를 위한 새 동기화 경로는 없다.** 수렴은 기존 장치(되감기·보정·서버 순서)가 그대로 보장한다.
- 새로 할 일은 세 가지다: ① 명령이 기억한 위치를 남의 편집에 맞춰 옮기기, ② 겹치면 막기, ③ 내 편집이
  충돌로 버려지면 그 명령도 스택에서 빼기.

## 3. 규칙

### 3.1 위치 옮기기
- 명령이 기억한 위치(구역·문단·글자, 셀 경로 포함)는 원격 기록이 들어올 때마다 그 기록의 지도로 옮긴다.
  캐럿을 옮기는 것과 같은 지도(`collabMapCaret` 계열)다. undo 스택과 redo 스택 모두.
- 다른 문단에서 문단 수가 바뀌는 편집(남의 Enter 등)은 인덱스만 옮기고 막지 않는다.

### 3.2 막기 (명령마다 "발자국" = 고친 문단 범위, 구조 명령은 구역)
명령 C 뒤에 들어온 원격 기록 R 중 하나라도 아래에 해당하면 C 는 막힘이다.
1. R 이 C 의 발자국 문단(셀 문단 포함)을 고쳤다 — 텍스트·서식 모두. (동시 편집 보정 §4.4 는 같은 문단의
   동시 입력을 합쳐 주지만, 되돌리기는 더 보수적으로 같은 문단이면 막는다.)
2. R 이 구조 편집·state 이고 C 와 같은 구역이다(2단계 §4.5 표의 "같은 구역" 정의).
3. C 가 스냅샷으로 되돌리는 명령(`SnapshotCommand`·`Submode*SnapshotCommand`, `restoreSnapshot` 류)이고 R 이
   **무엇이든** 있다 — 스냅샷 복원은 그사이 남의 편집까지 지운다.
4. C 의 되돌리기가 저장소에 의존하는 호출(`restoreDeleteFragment` 등, state)이고 R 이 같은 구역이다.

- 막힌 명령을 되돌리려 하면: 알림을 띄우고 그 명령을 스택에서 버린다(문서는 그대로). 다음 되돌리기는 그 아래
  명령으로 간다. 한 번 누름에 여러 단계를 건너뛰지 않는다(왜 안 됐는지 보이게).
- redo 도 같은 규칙. 새 로컬 편집이 생기면 redo 스택은 studio 규칙대로 비운다.

### 3.3 버려진 편집
- 내 미확정 편집이 충돌로 버려지면(엔진 `droppedEntries`, 꼬리 포함) 그 편집을 만든 명령도 스택에서 뺀다.
  그 명령의 기록 항목이 일부라도 버려졌으면 명령 전체를 뺀다. 그러려면 명령 ↔ 만든 기록 항목의 연결을 둔다.
- 되돌리기·다시 하기가 만든 기록이 버려지면 그 명령을 버린다(알림: "되돌리기가 다른 사람 편집과 겹쳐
  취소됐습니다").

### 3.4 스택을 비우는 때
- 제자리 재동기화·welcome(재접속 범위 밖, 세대 전환)·문서 교체: 위치가 의미를 잃으므로 비운다.
- catchup(재접속 범위 안): 원격 수신과 같으므로 3.1~3.2 로 처리하고 비우지 않는다.

## 4. 작업 (코드 세션)

- **U0 조사 (먼저, 30분 안):** 37종이 위치를 어떻게 들고 있는지(공통 타입/필드 vs 명령마다 다름), 각
  `undo()`/`execute()` 가 부르는 export 와 분류표의 sync·conc, 발자국을 명령에서 얻을 수 있는지, 입력 묶기
  규칙. 결과로 위치 옮기기 방식(공통 훅 하나 vs 명령별 구현)을 정해 보고한다. 명령별 구현이 필요하면 작업량이
  늘어나므로 그때 범위(아래 U2)를 다시 정한다.
- **U1 기본형:** 0002 패치에 history 협업 훅(위치 옮기기·막힘 판정·명령 ↔ 기록 연결)을 추가하고, 공동편집
  중 `suspendHistory` 대신 이 훅으로 되돌리기를 켠다. 대상: 글자 입력·삭제, 문단 나누기·합치기, 글자·문단
  서식, 셀 안 같은 것들. 그 밖의 명령은 3.2-3 규칙(뒤에 아무 원격 기록도 없을 때만)으로 허용.
- **U2 확장:** 표·그림·개체 이동·크기 같은 나머지 명령도 발자국과 위치 옮기기를 붙여 3.2-1·2 규칙으로 넓힌다.
- **U3 시험:**
  - 브라우저(두 탭, 지연 서버): ① A 1문단 입력, B 3문단 입력, A 되돌리기 → A 글자만 사라짐 ② A 입력 뒤 B 가
    같은 문단 편집 → A 되돌리기 막힘·알림·문서 그대로 ③ A 굵게, B 다른 문단 입력 → A 되돌리기로 굵게 해제
    ④ A Enter, B 다른 문단 편집 → A 되돌리기로 합쳐짐 ⑤ A 표 만들기 뒤 아무도 편집 안 함 → 되돌려짐 / B 가
    같은 구역 편집 → 막힘 ⑥ A 편집이 충돌로 버려짐 → 스택에서 빠짐 ⑦ redo, B 편집 뒤 redo 막힘
    ⑧ IME 입력 되돌리기 ⑨ 미확정 중 되돌리기(지연 서버) ⑩ 재접속 catchup 뒤 되돌리기.
  - 매 단계 digest 일치·재동기화 0. 표준 R5·R8 회귀.
  - 막힘 판정·위치 옮기기는 단위 시험(무작위 원격 기록 열에 대해 "막히지 않은 되돌리기 = 내 편집만 빠진 문서"
    를 이전 문서로 확인할 수 있는 경우).
- **기록:** 이 문서 끝 §기록에 행으로 남긴다. 알려진 한계는 2단계 §9 에서 "공동편집 중 되돌리기 꺼짐"을 지우고
  이 단계의 한계로 바꾼다.

## 5. U0 결과와 결정 (2026-11-27)

- **조사(코드 세션):**
  - 명령 37종에는 위치를 담는 공통 타입이 없고, 위치 필드의 모양은 9가지다(a~i).
  - 실행 경로는 셋이다: command 28곳, snapshot 89곳(붙여넣기·표·쪽·개체 삭제·대화상자 등), record 27곳(IME 조합 끝·끌기 등. WASM 을 먼저 부르고 history 에는 기록만).
  - 되돌리기 중 일부는 WASM 저장소에 의존한다: `restoreSnapshot`(문서 전체), `restoreDeleteFragment`(절대 문단 번호), `restoreSectionRaw`(구역 전체), `removeBorderFillTails`(문서 목록 꼬리를 개수로 지움).
  - 같은 명령도 실행 상황에 따라 저장소 의존 여부가 갈린다(InsertText 의 fragmentIds, DeleteSelection 의 본문·셀).
  - 공동편집 되감기는 collab-core 자체 스냅샷으로 하므로 studio 저장소는 되감기 뒤에도 살아 있다.
- **결정: 표 하나 + 범용 옮기기.** 명령 type → 위치 필드와 그 종류(DocumentPosition / (구역,문단) / 개체 앵커 / 문단 범위 / 각주 앵커), 그리고 실행 때의 저장소 의존 판정 함수를 표로 둔다. 종류마다 범용 옮기기 함수를 쓴다.
  - 표에 없는 type(업스트림이 나중에 더한 명령 포함)은 3.2-3 으로 처리한다(뒤에 원격이 하나라도 있으면 막음). "지원 기능은 빠르게, 새 기능은 느리지만 지원"과 같은 원칙이다.
  - 업스트림 `command.ts` 의 명령 클래스 목록과 표를 대조하는 시험을 둔다. 분류표의 drift 검사와 같은 역할이다.
- **옮기기:** Rust 에 `collabMapPositions(remote, catalog, positions[]) → [{pos, fate}]` 를 더한다. 바탕은 `map_caret`·`map_para` 다. fate(Kept/Touched/Gone)가 3.2-1 판정을 겸한다.
  - 미확정이 있을 때는 캐럿처럼 rebase 결과의 원격(미확정 뒤로 옮긴 것)으로 옮긴다.
  - 캐럿·선택 복원 필드(cursorBefore/After, selectionBefore/After, editContext)도 옮긴다.
  - 중첩 셀(cellPath 깊이 2 이상)은 U1 에서 3.2-3 으로 막는다. 지도를 넓히는 일은 U2 에서 한다.
- **저장소 의존 되돌리기의 막힘 규칙 (3.2-4 를 정밀화):**
  - `restoreSnapshot`, `removeBorderFillTails`: 3.2-3. `removeBorderFillTails` 를 쓰는 셀 테두리·배경도 여기에 든다. 분류표 why 의 "공동편집 중에는 되돌리기가 멈춰 부르지 않음" 문구를 고친다.
  - `restoreSectionRaw`: 같은 구역에 원격이 있으면 막는다(구역 전체를 되돌리므로).
  - `restoreDeleteFragment`: 조각의 문단 범위가 **옮겨지지 않았고**(앞쪽 문단 수 변화 없음) 발자국 문단을 남이 고치지 않았으면 허용한다. 그 밖에는 막는다. 본문 선택 삭제는 자주 쓰므로, 같은 구역이라는 이유만으로 막지 않는다.
- **버려진 편집:** 버려진 항목과 같은 문단에 발자국이 있는 명령은 같이 버린다(버려진 삽입이 오래된 명령의 위치를 어긋나게 할 수 있으므로). undo 열을 지도에 넣는 정밀화는 하지 않는다.
- **연결:** 명령 ↔ 기록 연결은 항목 단위다. 300ms 병합 때문에 명령과 묶음은 1:1 이 아니다. record 경로에서는 직전 명령 경계 뒤에 생긴 항목을 그 명령에 붙인다.
- **범위:**
  - U1: a·b·c·f + 캐럿·선택 필드, `collabMapPositions`, 연결, 3.3, 3.4.
  - U2: d·e·g·h(머리말·꼬리말·각주, 개체, 구역, 양식) + 중첩 셀 지도.
  - snapshot 경로 89곳은 U2 뒤에도 3.2-3 이다.
- **다음 후보 (U3, 지금은 하지 않음):** snapshot 경로의 문단 범위 복원.
  - 명령의 발자국(구역, 문단 범위, pd)을 남이 건드리지 않았으면, 스냅샷에서 그 문단 범위만 가져와 지금 문서의 해당 범위를 바꾼다(collab-core 보조). 동기화는 state 로 한다(스냅샷은 그 클라이언트에만 있으므로).
  - 표 만들기·붙여넣기 되돌리기가 "남이 아무 데나 고치면 막힘"에서 벗어난다.
  - 전제: 스냅샷의 DocInfo 참조(글자 모양 등)가 지금 문서에도 그대로 있어야 한다(추가만 되는지 확인 필요).
  - U2 사용 결과를 보고 정한다.
